# 掲示板移植メモ

## 実装済みの受け皿

現行システムに次の掲示板機能を追加している。

- 50件単位の新着一覧とページング
- タイトル・本文・投稿者のキーワード検索
- 新規投稿、日報テンプレート挿入
- 返信
- 閲覧回数
- ユーザー単位の「いいね」
- 投稿／返信ごとに最大5ファイル（各20MB）の添付
- 投稿者本人または権限1ユーザーによる削除
- スマートフォン表示

データは `t_board_threads`、`t_board_replies`、`t_board_attachments`、`t_board_likes` に保存する。旧システム側のIDを保持できるよう、投稿と返信には `legacy_id` を用意している。

## 旧掲示板から受け取るデータ

過去データを重複なく移すには、旧サーバーから次の情報を取得する。

### 投稿

- 旧投稿ID
- タイトル
- 本文（改行を保持）
- 投稿者名
- 投稿者メールアドレス（存在する場合）
- 投稿日時、最終更新日時
- 閲覧回数

### 返信

- 旧返信ID
- 親となる旧投稿ID
- 本文
- 投稿者名
- 投稿者メールアドレス（存在する場合）
- 投稿日時

### いいね・添付ファイル

- 投稿ごとのいいね数、またはユーザーを特定できる場合はユーザー別いいね
- 親となる旧投稿ID／旧返信ID
- 元ファイル名
- MIMEタイプ
- ファイル本体

旧ユーザーと現行 `m_user` の対応が取れない投稿は、表示用の投稿者名を保持し、`author_user_id` は `null` とする。この場合、削除は権限1ユーザーのみ可能になる。

## 本番反映手順

1. 本番DBと `storage/app` をバックアップする。
2. アプリケーションコードを反映する。
3. `php artisan migrate --force` を実行する。
4. Webサーバーから `storage/app/private/board` に書き込めることを確認する。
5. 少数のテスト投稿で、投稿・返信・添付・いいね・削除を確認する。
6. 旧データのエクスポートを受領後、`legacy_id` をキーにした再実行可能な取込処理で一括移行する。
7. 件数、先頭／中間／末尾の投稿、添付ファイルを突合してから旧掲示板を読み取り専用にする。

旧掲示板は50件×1,232ページの表示だったため、画面経由の手作業ではなく、旧サーバーのデータファイルまたは管理者向けエクスポートを利用する。
