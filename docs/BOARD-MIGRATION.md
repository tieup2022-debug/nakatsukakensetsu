# 掲示板移植メモ

## 実装済みの受け皿

現行システムに次の掲示板機能を追加している。

- 50件単位の新着一覧とページング
- タイトル・本文・投稿者のキーワード検索
- 新規投稿、日報テンプレート挿入
- 返信
- 閲覧回数
- ユーザー単位の「いいね」
- 投稿／返信ごとに最大5ファイル（各20MB）の添付
- 投稿者本人または権限1ユーザーによる削除
- スマートフォン表示

データは `t_board_threads`、`t_board_replies`、`t_board_attachments`、`t_board_likes` に保存する。旧システム側のIDを保持できるよう、投稿と返信には `legacy_id` を用意している。

## 旧掲示板から受け取るデータ

過去データを重複なく移すには、旧サーバーから次の情報を取得する。

### 投稿

- 旧投稿ID
- タイトル
- 本文（改行を保持）
- 投稿者名
- 投稿者メールアドレス（存在する場合）
- 投稿日時、最終更新日時
- 閲覧回数

### 返信

- 旧返信ID
- 親となる旧投稿ID
- 本文
- 投稿者名
- 投稿者メールアドレス（存在する場合）
- 投稿日時

### いいね・添付ファイル

- 投稿ごとのいいね数、またはユーザーを特定できる場合はユーザー別いいね
- 親となる旧投稿ID／旧返信ID
- 元ファイル名
- MIMEタイプ
- ファイル本体

旧ユーザーと現行 `m_user` の対応が取れない投稿は、表示用の投稿者名を保持し、`author_user_id` は `null` とする。この場合、削除は権限1ユーザーのみ可能になる。

## 本番反映手順

1. 本番DBと `storage/app` をバックアップする。
2. アプリケーションコードを反映する。
3. `php artisan migrate --force` を実行する。
4. Webサーバーから `storage/app/private/board` に書き込めることを確認する。
5. 少数のテスト投稿で、投稿・返信・添付・いいね・削除を確認する。
6. 下記のクローラーで旧データを取得し、`legacy_id` をキーにした再実行可能な取込処理で一括移行する。
7. 件数、先頭／中間／末尾の投稿、添付ファイルを突合してから旧掲示板を読み取り専用にする。

旧掲示板は1,232ページ、現存61,591投稿だったため、画面からの手作業ではなく下記クローラーを利用する。

## エクスポート機能がない場合のクロール

旧Hi-WAREは、ログイン後の画面を読み取り専用で巡回する。投稿・いいね追加・削除のエンドポイントは呼び出さない。パスワードはコマンド実行時の非表示入力だけに使用し、ファイルやログには保存しない。

旧サイトはHTTPで暗号化されていないため、管理者アカウントは使わない。閲覧だけできる移行専用アカウントを用意し、移行後に無効化する。

### 1. まず一覧1ページと投稿3件で試す

```bash
php artisan board:crawl-hiware \
  --user=移行専用ID \
  --start-page=1 \
  --end-page=1 \
  --limit=3 \
  --delay-ms=750
```

パスワードは実行後に非表示で尋ねられる。出力先は既定で次の場所になる。

自動実行する場合だけ、パスワード1行を記載したリポジトリ外のファイルを権限0600で用意し、`--password-file=/絶対パス` を指定できる。パスワード値をコマンド引数やチャットへ記載してはいけない。

```text
storage/app/private/legacy-board-export/
├── lists/       一覧ページごとのJSON
├── threads/     投稿・返信ごとの解析済みJSON
├── attachments/ 添付ファイル
└── failures.jsonl（失敗があった場合だけ）
```

### 2. 試験データを検証する

`--commit` を付けなければDBを書き換えず、件数とJSON・添付の整合性だけを検証する。

```bash
php artisan board:import-hiware \
  storage/app/private/legacy-board-export \
  --limit=3
```

### 3. 試験取込

本番DBのバックアップ後、3件だけ取り込む。

```bash
php artisan board:import-hiware \
  storage/app/private/legacy-board-export \
  --limit=3 \
  --commit
```

`legacy_id` で再実行時の重複を防止する。既に取り込まれた旧投稿は内容・閲覧数・旧いいね数を更新し、現行システムで追加されたいいねや返信は削除しない。

### 4. 全件クロール

試験結果を確認後に全1,232ページを取得する。既に完成している一覧JSON・投稿JSONは自動的にスキップされるので、停止しても同じコマンドで再開できる。

```bash
php artisan board:crawl-hiware \
  --user=移行専用ID \
  --start-page=1 \
  --end-page=1232 \
  --delay-ms=500
```

一覧だけ／詳細だけを分割する場合は、それぞれ `--phase=lists`、`--phase=details` を指定する。旧サーバーへの負荷を抑えるため `--delay-ms` は250未満にできない。

### 5. 全件取込

クロール後に件数を検証し、本番DBと `storage/app` を再度バックアップしてから実行する。

```bash
php artisan board:import-hiware \
  storage/app/private/legacy-board-export \
  --commit
```

旧ユーザー名が現行 `m_user.user_name` と完全一致する場合だけユーザーIDを関連付ける。一致しない退職者・旧ユーザーは表示名とメールアドレスを保持し、投稿の削除権限は現行の権限1ユーザーだけに限定する。
